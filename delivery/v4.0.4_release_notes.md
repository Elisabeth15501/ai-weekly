# AI Weekly Report v4.0.4 — Release Notes

发布日期：2026-10-03
Slug：`ai-weekly` · 版本：`4.0.4` · 许可证：MIT-0（ClawHub 全站强制）

## 一句话总结

v4.0.4 移除已过时的飞书 Webhook「通道 A」旁路，飞书投递统一收敛为单一、干净的飞书连接器（lark-cli）通道；功能与周报输出形态与 4.0.3 完全一致。

## 具体变更

### 代码
- `publish.py`：移除 Webhook 通道 A 相关实现（`resolve_webhook()`、`--webhook` 入参、`feishu_bot.push()`），改调用 `feishu_connector.send_card()`（lark-cli 子进程 + stdin 传递，令牌不写入磁盘）。
- `delivery/feishu_bot.py`：退化为纯标题卡片构造器，仅保留 `build_headline_card()`；发送职责移交连接器。
- `scripts/init_feishu_config.py`：移除 `--method webhook` / `do_webhook()` / `validate_webhook()`，现仅生成连接器推送目标 `delivery/feishu_target.json`。

### 文档
- 同步更新 README.md、SKILL.md、references/SKILL_full.md、references/FAQ.md、manifest.json：移除 Webhook 双通道对照表 / 模式 A / `--webhook` 示例，统一表述为「飞书连接器推送（密钥不落盘）」。

### 配置
- 删除已废弃的 `delivery/feishu_config.example.json`（含 `REPLACE_WITH_YOUR_TOKEN` 占位符）；新增 `delivery/feishu_target.example.json` 作为连接器推送目标示例。
- 修订 `releases/v3.3.0.md` 中一处含本地用户名与绝对路径的示例，去掉随包发布的 PII。

## 升级影响

- 若你此前通过 `--webhook` 投递周报，需改走飞书连接器：先以 `scripts/init_feishu_config.py` 生成 `delivery/feishu_target.json`（连接器推送目标），再由 `publish.py` 经 lark-cli 完成推送。旧的 Webhook 令牌（bot token / webhook URL）不再被读取，可另行清理。
- 其余周报生成、校验、gh-pages 部署流程与 4.0.3 完全一致，历史周报产物不受影响。

## 安全合规说明

- 飞书推送密钥全程经 lark-cli 子进程 + stdin 传递，不落盘、不进 `ps`，与 v4.0.0 起确立的「凭据不落盘」基线一致。
- 已无任何 Webhook 凭证文件（`delivery/feishu_config.example.json` 已删除，且无任何运行时将令牌写入磁盘的分支）；v4.0.3 已通过的 ClawHub 安全扫描结论在 v4.0.4 仍然成立——本次仅收敛通道，未引入新的凭据暴露面。
- 4.0.3 已通过 ClawHub 安全扫描，本次未新增可公开安全问题。

## 验证

- 合规门禁 `python scripts/compliance_check.py`：exit 0，无 BLOCKER / WARN。
- 单元测试 `pytest scripts/test_p1_guards.py`：11 passed（与 4.0.3 基线一致）。
- 端到端：`publish.py --dry-run` 复用样例报告成功构造连接器标题卡片（6 段、headlines=5，rc=0，不实际发送）；飞书投递通道与 4.0.3 一致（lark-cli 连接器），密钥经 stdin 传递不落盘。

## 升级方式

无需数据迁移。直接更新到 v4.0.4 即可；曾使用 `--webhook` 的用户按「升级影响」一节改走连接器。
