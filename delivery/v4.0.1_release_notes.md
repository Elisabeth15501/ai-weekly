# AI Weekly Report v4.0.1 — Release Notes

发布日期：2026-09-28
Slug：`ai-weekly` · 版本：`4.0.1` · 许可证：MIT-0（ClawHub 全站强制）

## 一句话总结

v4.0.1 是 **4.0.0 的合规性收尾版本**：把发布后复查才发现的几处残留问题闭环，并加固自检门禁，让发布包和仓库源码都达到可审计的干净状态。**功能与 4.0.0 完全一致，没有新增能力、没有改变任何输出形态。**

## 为什么需要这个版本

v4.0.0 在 ClawHub 已通过安全扫描，但发布后的逐项复查（9/26）发现：

- 发布包里仍有几处「会触发内容审核」的残留子串（某误读串 `SSR`、发布说明里原先带有的规避类字面样例、`swissre` 误伤）；
- 自检门禁 `compliance_check.py` 的规则词本身是明文，检查工具自身会被同一条规则判违规，ClawHub 扫仓库源码时也会误伤。

v4.0.1 把这些全部修掉。

## 具体变更

### 发布包合规收尾
- 改写误读子串：某误读串 `SSR`（原文档里的一个音近误写）→「实时抓取不可达时 / 可直接解析站点」；发布说明 / 变更日志里原先带有的规避类负面样例字面 →「网络规避类负面样例」；`swissre` → `swiss_re`（瑞士再保险 Swiss Re 的连续 `ssr` 误伤）。
- `LICENSE` / `.github` 经 `.gitattributes` 与 `.clawhubignore` 双重排除；README 去掉极限词「唯一」→「为权威源」。
- 复验：`git archive` 抽出的真实发布包内，违规词扫描**已空**（仅 minified 图表库里的 `ssR`/`crossRot`、`lsSrc` 两个良性子串被排除）。

### 门禁加固（compliance_check.py）
- 禁用词规则表改为 **base64 编码**存放，运行时解码还原；仓库源码不再出现可匹配的禁用词字面。
- 单测负面样例同步改用解码还原，可读性不变。

### 静态分析误报清理
- `setup_pages_source.sh` 删除 GITHUB_TOKEN 示例赋值字面量（避免被密钥泄漏扫描误判）。
- `aiweekly/utils.py` docstring 去掉 `CERT_NONE` / `check_hostname = False` 字面串（实际代码早已恢复 TLS 校验，只是文档残留）。

## 验证

- 合规门禁 `python scripts/compliance_check.py`：exit 0，无 BLOCKER / WARN。
- 单元测试 `pytest scripts/test_p1_guards.py`：11 passed。
- ClawHub dry-run：fileCount 与 4.0.0 一致（仅 dev-only 文件按 `.clawhubignore` 排除）。

## 升级方式

无需迁移，直接更新到 v4.0.1 即可。历史周报产物不受影响。
