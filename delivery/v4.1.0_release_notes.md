# AI Weekly Report v4.1.0 — Release Notes

发布日期：2026-10-08
Slug：`ai-weekly` · 版本：`4.1.0` · 许可证：MIT-0（ClawHub 全站强制）

## 一句话总结

v4.1.0 是**安全整改 + 分发可靠性 + 来源诚实性**版本：清掉最后一个凭据暴露面（T09，令牌不再经 `argv` 泄漏），把「飞书推送静默失败」这类故障从流水线第 6 步提前到第 0 步暴露，并消灭页脚上把人工誊录的历史基线混进「本周来源」的误导性引用。周报生成形态与 4.0.4 完全一致。

## 具体变更

- `scripts/deploy.py`（T09 安全整改）：Vercel / Netlify / Cloudflare Pages 三家 provider 的 token 由命令行参数改为经**子进程 `env`** 传递（`VERCEL_TOKEN` / `NETLIFY_AUTH_TOKEN` / `CLOUDFLARE_API_TOKEN`），令牌不再进入 `ps`；新增 `_register_secrets()` 登记本次凭据字面量供脱敏兜底，新增 `_redact()` 覆盖打印 / dry-run / 异常三条出口，`_run_cli()` 统一收口。

## 安全说明

### T09：凭据经 argv 泄漏（已修复）

**是什么**：`deploy.py` 的 Vercel / Netlify / Cloudflare Pages 三条 provider 路径原先把部署 token 以命令行参数形式传给子进程。`ps` 在部分 CI 镜像与部分 Windows 环境中对同机其他用户可见，令牌因此可被旁路读取——这是凭据泄漏面，不是理论风险。

**怎么修的**：
1. token 一律经**子进程 `env`** 传递（`VERCEL_TOKEN` / `NETLIFY_AUTH_TOKEN` / `CLOUDFLARE_API_TOKEN`），不再出现在 argv 中，令牌不进 `ps`。这与 v4.0.0 确立的 P0-4（GitHub Pages 凭据改走 `GIT_CONFIG_*`）、v4.0.4 确立的飞书连接器 stdin 通道同属一条「凭据不落 argv、不落盘」基线。
2. 新增 `_redact()` 集中脱敏，覆盖**打印 / dry-run / 异常**三条出口，避免「改了打印、漏了异常」这类半截修复；先整体脱敏再截断（反过来 `out[-500:]` 会在令牌被截断时漏出片段）。
3. 附**sentinel 回归测试**（`test_deploy_redact.py`，26 例）：以假 sentinel `SENTINEL_A1B2C3_SECRET_DO_NOT_LEAK` 跑三家provider 路径，断言它不出现在 stdout / stderr / 异常文本 / 下游 CLI 回显四处，从测试层锁死缺陷不复发。

### 飞书凭据为何曾导致推送静默失败，preflight 如何提前暴露

**故障链**：2026-10-05 那次周报，飞书推送在流水线第 6 步失败（rc=3）却被上游脚本吞掉——产物照常生成、校验 25/25 通过、`.run.log` 写着 `errors: 0`，用户直到手动追问才发现根本没收到消息。根因有两层：脚本不判退出码（已单独修复）+ **凭据问题直到第 6 步才暴露**。

`preflight.py`（SEC-12）解决第二层：把「凭据是否可用」从流水线第 6 步**提前到第 0 步**。它在生成产物之前调 `lark-cli doctor`，抽取三项决定推送成败的检查并翻译成人话可操作提示：

| 检查项 | 不通时的人话含义 |
|---|---|
| `identity_ready` | 飞书身份未就绪（完全推不了） |
| `bot_identity` | 飞书 bot 身份未就绪（发消息报 20140） |
| `app_resolved` | 飞书应用凭据无法解析 |

退出码 0 通过 / 1 不通过（stderr 给出修复步骤）/ 2 用法错误；`--json` 供 automation 消费，`--quiet` 成功静默。

## 升级影响

- **无数据迁移。** 周报生成、校验、部署流程与 4.0.4 完全一致，历史周报产物不受影响。
- 唯一需要留意的是**页脚来源标注**：页脚现在把「静态快照引用」与「本周信号来源」分开列出。如果你此前把页脚当作单一来源清单使用（读者默认「列出来的都是这周抓的」），4.1.0 起需要区分阅读——人工誊录的历史基线不再混进本周来源。这是有意为之的诚实性修正，不是渲染bug。
- 市场 / 融资快照阈值默认 90 天（`SNAPSHOT_STALE_DAYS`），可用 `--check-snapshot` 覆盖。快照过期后页面会显式标注「已过期」而不是静默沿用旧数；读不到 `assets/market_snapshot.json` 时回退内置 `_FALLBACK_*` 常量并同样标注。若你曾按 `.gitignore` 自行排除该文件，请确保它随包分发。
- 部署到 Vercel / Netlify / Cloudflare Pages 的用户无需改动配置或命令，token 读取顺序与优先级完全不变（显式参数 > 环境变量 > `*_config.json`），仅传递通道由 argv 改为 env。
- `preflight.py` 需要宿主的 lark-cli（由连接器安装于 `~/.workbuddy/binaries/node/cli-connector-packages/`）；该目录实测**不在用户 PATH** 内，脚本已内置回退探测。仅在跑飞书推送流水线时才需要，纯生成周报不依赖它。

## 已知局限
