# ai-weekly v3.4.1 — 实时排行榜复盘 R1–R4 修复

> 发布日期：2026-09-07
> 前置版本：v3.4.0（2026-09-05，SkillHub 评测驱动优化封版）

本版本对应 [SkillHub 评测优化方案 v2](https://github.com/Elisabeth15501/ai-weekly/wiki/AI-Weekly-SkillHub-Optimization-Plan-v2) 第十节「实时排行榜复盘」的 R1–R4 修复。核心目标：让实时榜单来源标注与真实数据严格一致、慢源不再因抖动空榜、刷新不再依赖会话存活。

## 为什么是 3.4.1

v3.4.0 把"排行榜实时更新"机制搭好了骨架（多源池 + 每日 09:00 自动化 + 镜像回退），但复盘发现 5 处隐患。本版本闭环 R1–R4（R5 口径已固化）：来源透明化、国内源诚实化、慢源超时提额、系统级调度兜底。版本号取 3.4.1（补丁级）：纯健壮性修复，零破坏性改动。

## Fixed

- **R1 开源榜来源透明**（`leaderboard.py` / `leaderboard_fetch.py` / `news_site_template.html`）
  - `ls`(LLM-Stats) 源国内实测 0% 实时率，开源榜左列此前用 `dl`(DataLearner) 数据却标"LLM-Stats"
  - 改为按真实命中源动态选 `label`/`criteria`/`url`，命中 `dl` 即显示 `DataLearner · 开源模型榜`
  - 新增 `LB_CRITERIA["dl"]` 真实评分标准（HLE 为主分）；前端图例与兜底默认值同步诚实化

- **R2 国内源诚实化**（`leaderboard.py` / `leaderboard_sources.py`）
  - 探测确认 OpenCompass/SuperCLUE/ModelScope 均为 SPA、简单 HTTP 抓不到（能力性限制非 bug）
  - 删除"oc/sv 国内实时源回退"两段 `if` 死代码（实测 0% 永不触发）
  - cn 综合榜如实依赖 aa/lm 实时源、二者皆失败回退 `cn_snap` 静态快照（已标 `is_cache`）；三源仍留池作 best-effort

## Changed

- **R3 慢源超时提额**（`leaderboard_sources.py` / `leaderboard_fetch.py`）
  - LMArena 超时 60→75s、Hugging Face 45→60s、Artificial Analysis 45→60s
  - 整体墙钟硬上限 `OVERALL_FETCH_CAP_S` 180→240s，给慢源留足重试墙钟（3×75s=225s < 240s）
  - 说明：三慢源已带 hf-mirror 等镜像回退，提额主要缓解"能通但慢"的抖动空榜

- **R4 刷新编排更稳健**（`refresh_deploy.py`）
  - `--api-json`/`--output` 缺省自动落位（`<skill>/workspace/news.json` / `AI_News_live.html`），便于系统调度无参调用
  - 生成步骤失败自动重试 1 次（网络抖动避免一次性放弃整轮刷新）
  - 推送失败仍显式非零退出，不误报"实时榜已部署"

## Added

- **R4 系统级调度兜底**（`scripts/install_scheduler.py`）
  - 按 OS 自动选 Windows 任务计划 / Linux cron，每日 09:00 调用 `refresh_deploy.py` 刷新排行榜
  - `--uninstall` / `--dry-run` / `--time` 选项齐全；预检 `workspace/news.json` 存在
  - WorkBuddy automation 仍作即时触发，系统调度仅兜底（会话不在线也能刷新）

## 验证（本版本发布前全绿）

- R1 单测（mock `ls` 空 + `dl` 有数据）：开源榜左列 `source` 输出 `DataLearner · 开源模型榜`、`is_cache=False`
- R4 `install_scheduler.py --dry-run` 正确拼装 schtasks/cron 命令（未落盘）
- `py_compile` 全部通过；`leaderboard.py` 797 行 < 800 行模块体量守护上限
