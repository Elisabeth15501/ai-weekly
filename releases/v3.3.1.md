# ai-weekly v3.3.1 — 对抗式安全/健壮性审查收尾 + 工程可读性

> 发布日期：2026-09-03
> 前置版本：v3.3.0（2026-08-27，GitHub Pages 自动部署链路封版 + 认证/安全修复）

本版本是对《AI Weekly 对抗式审查报告（2026-09-02）》的收尾：把审查标记的剩余项（R6、S1、S2、N2）全部闭环，并随发布把此前已落地、尚未随正式版本封版的 C1/R1–R5 一并标注。过程中不引入任何用户可见的行为变化——卡片结构、报告 schema、部署链路均与 v3.3.0 兼容。

## 为什么是 3.3.1

v3.3.0 封版了「部署 + 飞书链接可用」这条主链路后，一份对抗式审查报告指出若干安全/健壮性/可读性缺口。其中 C1/R1–R5 已在日常工作流中修掉并提交，但 R6、S1、S2、N2 仍未正式封版；本版本把它们全部落地、加回归测试、跑通验证套件，并随本次发布统一对外。版本号取 `3.3.1`（补丁级）：纯内部加固与可读性，无新功能、无破坏性变更，符合语义化版本的 patch 语义。

## Added

- 无新增功能。

## Changed

- **飞书连接器通道根治（R6）**：`delivery/feishu_connector.py` 的 `send_card` 不再把整卡 JSON 作为 `--content` 命令行参数传给 lark-cli（受 Windows 命令行 ~8191 字符上限约束，满配卡片会静默 spawn 失败且无报错）。改为经 `lark-cli api POST /open-apis/im/v1/messages --data -` 的 **stdin** 传入，大卡片 body 完全不进 argv，从根本上消除上限。已用 `--dry-run` 验证新通道生成的请求体与原 `im +messages-send` 路径逐字节一致，并真实发送验证（`message_id` 回传正常）。
- **优先别名逻辑抽纯函数（S1）**：`scripts/aiweekly/insights.py` 的 `_auto_keywords` 内联脆弱保送逻辑（多次重算 `present` 集合、`[:top_n]` 截断后替换末位，存在 off-by-one 风险）抽成模块级纯函数 `_apply_priority_alias(ranked, cands, top_n)`，语义逐字节等价，附 3 条单测。
- **榜源并行整体截止（S2）**：`scripts/aiweekly/leaderboard_fetch.py` 早已实现并发 + 单源 `try/except` 隔离 + 顺序回退；本版本补审查真正担忧的剩余缺口——整体墙钟硬上限 `OVERALL_FETCH_CAP_S = 180`：`as_completed` 改为 `wait(timeout=)`，超时源标记 `timeout` 跳过，`shutdown(wait=False, cancel_futures=True)` 非阻塞退出。最坏总延迟从「无上限（单源 120s × 3 重试、且须等所有源跑完）」压死在 ~180s，杜绝「一个慢源拖垮整份周报生成」。

## Fixed

- **安全/健壮性审查闭环（C1 / R1 / R2 / R3 / R4 / R5）**（已在此前提交落地，本版本随发布标注）：
  - **C1 / N1**：`delivery/feishu_bot.py` 的 `_md_escape` 原为死代码（仅插零宽空格、未转义），RSS 标题/摘要直进 lark_md 致排版崩坏；重写为真正转义器（转义 `* _ \` ~ [ ] ( ) > #` 为全角），全路径接入卡片构造。
  - **R1**：`scripts/publish.py` 的 `float(score)` 对脏值（`"N/A"` / `"high"`）直接崩；新增 `_safe_score` 兜底（脏值 → `0.0`）。
  - **R2**：关键词硬截断 `[:6]` 吃掉 P2 保送词「牛来」；改为截断前按保送集优先排序。
  - **R3 / R4**：`scripts/refresh_deploy.py` 把 PAT 写进 git argv（共享主机泄露风险），且非 Windows 环境静默退化成「请手动 push」并 `exit 0`（实时榜可能从未部署）；改为 PAT 走 `GIT_CONFIG_COUNT/KEY_0/VALUE_0` 环境变量注入、推送失败返回非零码 + 明确告警。
  - **R5**：`scripts/aiweekly/leaderboard.py` 的 `canon_key`/`_norm_model` 后缀剥离过激进致 `GLM-5.3 ≡ GLM-5.3-Flash` 撞键；改为后缀感知（命中已知后缀时归一键追加 `~<suffix>`，如 `glm53~flash`）。
- **N2（可读性）**：`scripts/publish.py` 三处 best-effort `except Exception # noqa: BLE001` 补齐「为何必须吞」注释：
  - `_PRIORITY_ALIASES` 导入失败 → 回退最小保送集 `{牛来}`，绝不阻断卡片组装；
  - 飞书推送传输异常 → 末段 best-effort 分发，失败绝不能中断已生成的报告，只记 `rc=1` 继续；
  - gh-pages 部署异常 → 部署为 best-effort，失败不回滚已生成的报告，仅告警并记录。

## 安全提醒

R3 修复后，`refresh_deploy.py` 不再把 PAT 写入命令行参数，凭据仅经进程环境变量注入 git，避免长时间驻留进程 argv 带来的泄露面。`.github_token`（含 `repo` + `pages:write` 的明文 Classic PAT）仍 gitignore、不入仓库，不用时可在 GitHub 随时 revoke 重发。
