# ai-weekly v3.3.0 — GitHub Pages 自动部署链路封版 + 认证/安全修复

> 发布日期：2026-08-27
> 前置版本：v3.2.0（2026-08-17，飞书双推送路径文档化 + 版本对齐）

本版本把「**GitHub Pages 自动部署 + 飞书卡片里『查看完整周报』链接可用**」这条核心链路正式封版，并修通此前一直卡住的免交互 PAT 推送认证、CI 诊断与安全正则加固，同时修正文档中与实测不符的描述。

## 为什么是 3.3.0

v3.1.1 起飞书推送已可用，但卡片里的「查看完整周报」按钮指向一个 GitHub Pages 地址——而 Pages 源、部署脚本、免交互推送在 v3.2.0 时都还没真正跑通。本版本补齐并验证了整条链路：

- 新增 `gh-pages` 分支部署流水线（`deploy_ghpages.py` + `run_report.sh deploy` + `publish.py --deploy`）；
- 修通 deploy 的免交互 PAT 推送（这是此前飞书链接 404 的根因）；
- 加固 CI 与安全正则，并修正文档（Fine-grained→Classic PAT、自动化调度日 周六→周一）。

## Added

- **GitHub Pages 部署接入流水线**：新增 `scripts/deploy_ghpages.py`，用 git worktree 把生成的周报 HTML 推到 `gh-pages` 分支根目录（飞书/钉钉卡片 `view_url` 即指向此地址），并自动累加根 `index.html` 存档页（列出各期、最新高亮）。
  - `--no-push`：离线仅本地提交不推送（待网络恢复后 `git push origin gh-pages`）。
  - `--switch-pages`：部署后通过 GitHub API 把 Pages 源切到 `gh-pages / /root`（需 `pages:write` 的 token，一次性）。
  - `--dry-run`：只做 worktree + 复制 + index 预览，不提交不推送。
- **`run_report.sh deploy` 子命令**：把部署作为流水线一等步骤封装（`bash run_report.sh deploy --html AI_News.html`）。
- **`publish.py --deploy`**：推送飞书卡片的同时顺带部署到 gh-pages（需配合 `--html`）；透传 `--no-push` / `--switch-pages`。

## Changed

- **停用 `.github/workflows/mirror.yml`**（`if: false` 移至 job 级，修复 `Invalid workflow file`）：原先的 Actions artifact Pages 部署与 gh-pages 分支来源互斥，会破坏分支部署；如需恢复 Actions 部署，需先把仓库 Pages 源切回 "GitHub Actions"。
- README / SKILL.md 的「GitHub Pages」说明改为描述 gh-pages 分支部署模型与首次启用步骤。
- **首次启用文档修正**：Pages 源切换改用 **Classic PAT**（Fine-grained 不被 Pages API 支持，常 403）。
- **SKILL.md 自动化调度日修正**：描述与自动化模板的 `rrule` 由 `BYDAY=SA`（周六）改为 `BYDAY=MO`（周一 09:00），与实际 automation 一致。
- **CI 诊断（ci.yml）**：`pip install` 加 `--no-cache-dir`；单测前 `pytest --version` 显式诊断；失败用 `--tb=short` 输出短堆栈，便于定位环境层问题。

## Fixed

- **部署推送认证修正（deploy_ghpages.py）**：原 `http.extraheader=AUTHORIZATION: Bearer <token>` 在 git smart HTTP 上无效（GitHub 报 `invalid credentials`）。改为用 `url.insteadOf` 把 **Classic PAT** 嵌进远端 URL（Basic 认证），并清空 `credential.helper` 避免 Windows wincred 在无 tty 环境卡死超时。支持从 `.github_token` 文件（已 gitignore）或环境变量 `GITHUB_TOKEN`/`GH_TOKEN` 读取。
- **mirror.yml 合规**：顶层 `if: false` 改为 job 级 `if: false`，修复 GitHub Actions `Invalid workflow file`。
- **安全加固（validate_checks/v2.py）**：`<style>`/`<script>` 过滤正则增加单词边界 `\b` 与尾部容错 `[^>]*`，防止误删 `<stylesheet>`/`<scriptx>`、且闭合标签带尾字符时漏过滤（CodeQL CWE-20）。

## 首次启用（一次性）

1. 生成 Classic PAT（GitHub → Settings → Developer settings → PAT → Tokens (classic)，勾选 `repo` + `pages:write`），写入本地 `.github_token`（已 gitignore，不进仓库）：
   ```powershell
   Set-Content -NoNewline "C:/Users/elisa/.workbuddy/skills/ai-weekly/.github_token" "ghp_你的PAT内容"
   ```
2. 部署当周报告（自动写 `.nojekyll` 并推送）：
   ```bash
   bash run_report.sh deploy --html AI_News_YYYY-MM-DD.html
   ```
3. 仓库 **Settings → Pages → Source** 设为 `gh-pages / /root`（或首次 `run_report.sh deploy --switch-pages`）。

> 之后每周自动化（周一 09:00）带的 deploy 步骤会用 `.github_token` 自动推送，飞书卡片链接不再 404。

## 安全提醒

`.github_token` 是含 `repo` 全写权限的明文 Classic PAT。文件已 gitignore、不入仓库；不用时可在 GitHub 随时 revoke 重发。另建议：在 `validate_report.py` 增一条「发布前扫描本地绝对路径 / 密钥特征」的守护，防止报告内容意外泄露。
